# tmux Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give tmux a HyDE-theme-following status bar (live-recolored on theme/wallpaper switch), a which-key hint menu, and a curated set of daily-driver plugins.

**Architecture:** Two layers. (1) A static home-manager module `modules/hm/tmux.nix` holds options, keybindings, plugins, and a theme hook that sources a generated color file with a hardcoded Mocha fallback. (2) A HyDE wallbash template `tmux.dcol` regenerates `~/.cache/hyde/wallbash/tmux.conf` from the live palette and re-sources it into the running `main` server on every theme/wallpaper/mode switch.

**Tech Stack:** Nix / home-manager (`programs.tmux`), HyDE wallbash `.dcol` templates, tmux 3.x, `pkgs.tmuxPlugins.*`.

**Spec:** `docs/superpowers/specs/2026-06-09-tmux-improvements-design.md`

## Testing note (read first)

This is declarative Nix config — there is **no unit-test framework**. Home-manager is wired into this repo as a **NixOS module** (the flake exposes only `nixosConfigurations`; there is **no** `.#hm` output — the CLAUDE.md `nix run .#hm` note does not apply here). Consequences:

- **Building/rendering is non-sudo** and is the per-change automated gate.
- **Applying needs `sudo nixos-rebuild`**, which per CLAUDE.md the **user** runs. Use `test` (reverts on reboot) for the first apply, then `switch` once happy.

The automated gate per change (all non-sudo):
1. **Evaluation** — `nixos-rebuild dry-build --flake .#xps13-9320` must succeed (catches Nix errors, bad option names, missing packages).
2. **Config-load validation** — render the tmux.conf via Nix and load it on a throwaway socket so a syntax error fails loudly without touching the live `main` session:
   ```bash
   P=$(nix build --no-link --print-out-paths \
     '.#nixosConfigurations.xps13-9320.config.home-manager.users.dori.xdg.configFile."tmux/tmux.conf".source')
   tmux -L wktest -f "$P" new-session -d \; kill-server && echo "CONFIG OK"
   ```
   (Verified working: this attr path renders the rendered `~/.config/tmux/tmux.conf` content directly.)

The remaining checks are **manual behavioral** (status bar appearance, live recolor, plugin keys), written as explicit steps with exact commands and expected results.

## Task 1: Create the wallbash theme template

**Files:**
- Create: `modules/hm/home/wallbash/tmux.dcol`

The header line is `target|command`. HyDE `eval`s the target (so `${cacheDir}` = `~/.cache/hyde` expands) and runs the command via `bash -c` after writing the file (so the running `main` server is re-sourced). Body uses `<wallbash_*>` placeholders that wallbash sed-substitutes with live hex colors. The status bar is intentionally **glyph-free** (no powerline arrows) so it does not depend on a Nerd Font.

- [ ] **Step 1: Write the template**

Create `modules/hm/home/wallbash/tmux.dcol` with exactly:

```
${cacheDir}/wallbash/tmux.conf|tmux source-file ${cacheDir}/wallbash/tmux.conf 2>/dev/null || true
# Autogenerated by HyDE wallbash — tmux theme following the active palette.
# pry1 = primary background, txt1 = text, 1xa6/1xa7 = bright accents, 1xa2 = dim accent.

set -g status on
set -g status-justify left
set -g status-style "bg=#<wallbash_pry1>,fg=#<wallbash_txt1>"

set -g status-left-length 40
set -g status-left "#[fg=#<wallbash_pry1>,bg=#<wallbash_1xa6>,bold] #S #[default] "

set -g window-status-format " #I #W "
set -g window-status-current-format "#[fg=#<wallbash_pry1>,bg=#<wallbash_1xa6>,bold] #I #W #[default]"
set -g window-status-separator ""

set -g status-right-length 60
set -g status-right "#[fg=#<wallbash_1xa7>] %Y-%m-%d #[fg=#<wallbash_pry1>,bg=#<wallbash_1xa6>,bold] %H:%M "

set -g pane-border-style "fg=#<wallbash_1xa2>"
set -g pane-active-border-style "fg=#<wallbash_1xa6>"
set -g message-style "bg=#<wallbash_1xa6>,fg=#<wallbash_pry1>"
set -g message-command-style "bg=#<wallbash_1xa6>,fg=#<wallbash_pry1>"
set -g mode-style "bg=#<wallbash_1xa6>,fg=#<wallbash_pry1>"
```

- [ ] **Step 2: Validate the body produces valid tmux config (simulate substitution)**

Substitute the live palette from `shell-colors` into a copy and load it on a throwaway socket. This proves the body is syntactically valid tmux without triggering a real theme switch:

```bash
# shellcheck disable=SC1090
source ~/.cache/hyde/wallbash/shell-colors
sed -e "s/<wallbash_pry1>/${wallbash_pry1#\#}/g" \
    -e "s/<wallbash_txt1>/${wallbash_txt1#\#}/g" \
    -e "s/<wallbash_1xa2>/${wallbash_1xa2#\#}/g" \
    -e "s/<wallbash_1xa6>/${wallbash_1xa6#\#}/g" \
    -e "s/<wallbash_1xa7>/${wallbash_1xa7#\#}/g" \
    modules/hm/home/wallbash/tmux.dcol | tail -n +2 > /tmp/tmux-theme-test.conf
tmux -L wktest -f /tmp/tmux-theme-test.conf new-session -d \; kill-server && echo "THEME BODY OK"
rm -f /tmp/tmux-theme-test.conf
```

Expected: prints `THEME BODY OK`. (The `#...` in shell-colors values keep their `#`; the `s/.../${var#\#}/` strips the leading `#` so the substituted hex re-gains exactly one `#` from the template's `#<...>`.)

- [ ] **Step 3: Commit**

```bash
git add modules/hm/home/wallbash/tmux.dcol
git commit -m "feat(tmux): wallbash theme template"
```

## Task 2: Create the static tmux module

**Files:**
- Create: `modules/hm/tmux.nix`

Holds all static tmux config. Options mirror the current inline block plus sensible additions. Plugins use the verified `pkgs.tmuxPlugins` attrs. The which-key XDG flag is set in that plugin's own `extraConfig` so it is emitted immediately before the plugin loads (required: the plugin's autobuild otherwise writes into the read-only nix store and fails). The theme hook sources the generated file if present, else applies a hardcoded Catppuccin Mocha fallback.

- [ ] **Step 1: Write the module**

Create `modules/hm/tmux.nix` with exactly:

```nix
{ pkgs, ... }:

{
  home.packages = [
    pkgs.fzf # required by tmux-fzf and extrakto
    pkgs.wl-clipboard # wl-copy/wl-paste for yank on Wayland
  ];

  # Persistent multiplexer for Claude agent sessions (see modules/system/memory.nix).
  # secureSocket=false puts the socket in /tmp so the server outlives the /run/user
  # lifetime; with linger enabled the `cz` session survives a forced logout.
  programs.tmux = {
    enable = true;
    secureSocket = false;
    terminal = "tmux-256color";
    escapeTime = 10;
    historyLimit = 50000;
    mouse = true;
    baseIndex = 1;
    keyMode = "vi";
    focusEvents = true; # needed by vim-tmux-navigator and resurrect

    plugins = with pkgs.tmuxPlugins; [
      vim-tmux-navigator # C-h/j/k/l across nvim splits and tmux panes
      yank # copy to system clipboard (uses wl-copy on Wayland)
      extrakto # prefix+Tab: fzf-grab paths/urls/words off the screen
      tmux-fzf # prefix+F: fuzzy session/window/pane switcher
      {
        plugin = resurrect;
        extraConfig = ''
          set -g @resurrect-capture-pane-contents 'on'
        '';
      }
      {
        plugin = continuum;
        extraConfig = ''
          set -g @continuum-save-interval '15'
          set -g @continuum-restore 'off'
        '';
      }
      {
        plugin = tmux-which-key;
        # NixOS: the plugin's autobuild copies into its (read-only) store dir and
        # fails. XDG mode relocates config + built init under ~/.config and
        # ~/.local/share. Must be set before the plugin loads — this block is
        # emitted immediately before its run-shell.
        extraConfig = ''
          set -g @tmux-which-key-xdg-enable 1
        '';
      }
    ];

    extraConfig = ''
      # Keep CWD when splitting/creating windows
      bind '"' split-window -v -c "#{pane_current_path}"
      bind '%' split-window -h -c "#{pane_current_path}"
      bind c new-window -c "#{pane_current_path}"

      # Reload config
      bind r source-file ~/.config/tmux/tmux.conf \; display-message "tmux.conf reloaded"

      # --- Theme: follow HyDE (wallbash) with a Mocha first-run fallback ---
      # The wallbash template regenerates ~/.cache/hyde/wallbash/tmux.conf on every
      # theme/wallpaper switch and re-sources it into the running server.
      if-shell '[ -f ~/.cache/hyde/wallbash/tmux.conf ]' \
        'source-file ~/.cache/hyde/wallbash/tmux.conf' \
        ' \
          set -g status on ; \
          set -g status-justify left ; \
          set -g status-style "bg=#1e1e2e,fg=#cdd6f4" ; \
          set -g status-left-length 40 ; \
          set -g status-left "#[fg=#1e1e2e,bg=#cba6f7,bold] #S #[default] " ; \
          set -g window-status-format " #I #W " ; \
          set -g window-status-current-format "#[fg=#1e1e2e,bg=#cba6f7,bold] #I #W #[default]" ; \
          set -g window-status-separator "" ; \
          set -g status-right-length 60 ; \
          set -g status-right "#[fg=#b4befe] %Y-%m-%d #[fg=#1e1e2e,bg=#cba6f7,bold] %H:%M " ; \
          set -g pane-border-style "fg=#313244" ; \
          set -g pane-active-border-style "fg=#cba6f7" ; \
          set -g message-style "bg=#cba6f7,fg=#1e1e2e" ; \
          set -g mode-style "bg=#cba6f7,fg=#1e1e2e" \
        '
    '';
  };
}
```

- [ ] **Step 2: Verify the file parses as Nix**

Run: `nix-instantiate --parse modules/hm/tmux.nix >/dev/null && echo "NIX PARSE OK"`
Expected: prints `NIX PARSE OK`.

- [ ] **Step 3: Commit**

```bash

git commit -m "feat(tmux): static module with plugins, keybindings, theme hook"
```
