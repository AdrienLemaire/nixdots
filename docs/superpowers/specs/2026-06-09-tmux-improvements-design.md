# tmux Improvements — Design

Date: 2026-06-09
Status: Approved (pending spec review)

## Goal

Improve the tmux setup with three things the user asked for:

1. **System theme colors** — tmux follows the live HyDE desktop theme (currently
   a wallpaper-derived purple palette; HyDE was on Catppuccin Mocha).
2. **Shortcut hints** — a discoverable key menu via `tmux-which-key`.
3. **Useful daily-driver plugins** — curated for the user's workflow (one
   persistent `main` session hosting Claude agent windows, nvim editing,
   OOM/logout-resilient long-lived sessions).

## Context

Current state (`modules/hm/default.nix:32`): a minimal `programs.tmux` block —
`mouse`, 50k history, `secureSocket = false`, `tmux-256color`, `escapeTime 10`.
No theme, no plugins, no custom keybindings.

- `cz()` helper (`modules/hm/home/zshrc:13`) = `tmux new-session -A -s main` — a
  single long-lived session. Built to survive logout/OOM (see
  `modules/system/memory.nix`); it effectively never restarts.
- Live server socket: `/tmp/tmux-1000/default` (`secureSocket = false`,
  `TMUX_TMPDIR` unset).
- Editor is nvim; shells are zsh + nushell.

### HyDE wallbash mechanism (verified from engine source)

HyDE themes every app through **wallbash**: `.dcol` templates in
`~/.config/hyde/wallbash/always/` are processed on **theme / wallpaper / mode
switch**, producing color files in `~/.cache/hyde/wallbash/` and running an
optional reload command. Verified in `~/.local/lib/hyde/color.set.sh`:

- Header line is `target|command`.
- `target` is `eval`'d (line 148) → `$HOME`, `${cacheDir}`, `${confDir}` expand.
- `command` runs via `bash -c "${exec_command}" &` (line 173) → an inline
  `tmux source-file …` reload command works; no separate script file needed.
- `WALLBASH_SCRIPTS` resolves to `<this-tree>/wallbash/scripts` (line 109).
- Body lines carry `<wallbash_*>` placeholders, sed-substituted with live colors.

A user-added `tmux.dcol` is fully supported. Existing apps using this exact
pattern: cava, discord, gtk, spotify.

## The Catppuccin decision

"Catppuccin mocha" and "follow HyDE theme" conflict: the catppuccin tmux plugin
is a *fixed* palette, while following HyDE means tracking its *dynamic* wallbash
colors. The user chose **Follow HyDE**, so:

- **Drop the catppuccin plugin.** Style the status bar directly from wallbash
  colors — the same source every other themed app uses (KISS/DRY).
- Consequence: the live palette is wallpaper-derived (currently purple
  `#1B1321`), not textbook mocha `#1e1e2e`. tmux matches the desktop, not a
  catppuccin screenshot. Confirmed acceptable by the user.
- **Mocha remains only as the first-run fallback** (before any theme regen has
  produced `tmux.conf`).

## Architecture — two layers

### Layer 1: Static config — `modules/hm/tmux.nix` (new module)

Extract the current inline `programs.tmux` block from `default.nix` into its own
module (1 file = 1 concern), imported from `modules/hm/default.nix`. Contents:

- **Options:** keep existing (mouse, `historyLimit 50000`, `secureSocket false`,
  `terminal tmux-256color`, `escapeTime 10`); add `base-index 1`,
  `pane-base-index 1`, `renumber-windows on`, vi copy-mode (`mode-keys vi`),
  `focus-events on` (required by vim-tmux-navigator and resurrect),
  keep-cwd splits, and a reload key (`prefix + r`).
- **Prefix:** keep `C-b` (unchanged, per user choice).
- **Plugins** (`programs.tmux.plugins`, all confirmed present in nixpkgs
  `tmuxPlugins`):
  - `tmux-which-key` — shortcut hint menu, triggered by `prefix` + `Space`
    (explicit trigger only; see "which-key reality" below).
  - `vim-tmux-navigator` — seamless `C-h/j/k/l` between nvim splits and panes.
  - `resurrect` — save/restore session layout + cwd.
  - `continuum` — **save-only** (15-min snapshots); auto-restore **disabled** to
    avoid fighting the `cz` `new-session -A` flow. Manual restore via
    `prefix + Ctrl-r` (resurrect default).
  - `tmux-fzf` — fuzzy session/window/pane switcher.
  - `extrakto` — fzf-grab paths/URLs/words off the screen.
  - `yank` + `wl-clipboard` package — clipboard integration on Wayland.
- **Theme hook (end of config):**
  ```
  if-shell '[ -f ~/.cache/hyde/wallbash/tmux.conf ]' \
    'source-file ~/.cache/hyde/wallbash/tmux.conf' \
    '<inline mocha fallback status styling>'
  ```

### Layer 2: Dynamic theme — `tmux.dcol` wallbash template

A new template deployed via `modules/hm/files.nix` (`home.file`) to
`~/.config/hyde/wallbash/always/tmux.dcol`. No collision risk — HyDE ships no
`tmux.dcol`.

```
${cacheDir}/wallbash/tmux.conf|tmux source-file ${cacheDir}/wallbash/tmux.conf 2>/dev/null || true

# Autogenerated tmux theme — body styles the status bar from wallbash colors:
#   <wallbash_pry1>  primary background
#   <wallbash_txt1>  foreground text
#   <wallbash_1xa6>  accent (active window / highlights)
#   ...
set -g status-style "bg=#<wallbash_pry1>,fg=#<wallbash_txt1>"
# (full status-left / status-right / window-status styling to be filled in)
```

On every theme/wallpaper/mode switch HyDE regenerates
`~/.cache/hyde/wallbash/tmux.conf` and runs the inline reload, which re-sources
into the running `main` server. **This live-reload is the critical path** — the
`main` session never restarts, so without it colors would never update.

Verified: `tmux source-file` against the live `/tmp/tmux-1000/default` socket
round-trips correctly; `TMUX_TMPDIR` is unset so themeswitch's `bash -c` targets
the same default socket.

## which-key reality (vs which-key.nvim)

tmux has **no "pause-then-reveal" primitive** — there is no timeout-triggered
popup. So the LazyVim experience (menu auto-appears after the leader, as
mappings become available) is **not achievable** in tmux. `tmux-which-key`
(explicitly modeled on which-key.nvim/emacs-which-key) instead opens its menu on
an **explicit trigger key**.

Decision: trigger via **`prefix` + `Space` only** (the plugin's `prefix_table`).
No no-prefix `root_table` chord — the default `C-Space` would collide with
fcitx5, and the user opted for the zero-conflict two-step trigger.

### NixOS / declarative build requirement

`tmux-which-key`'s init script copies its example config into the plugin's own
directory and runs `build.py` there. On NixOS that directory is the **read-only
nix store**, so the default autobuild fails. The plugin supports immutable OSes
via XDG mode: set `@tmux-which-key-xdg-enable 1`, which relocates config to
`$XDG_CONFIG_HOME/tmux/plugins/tmux-which-key/config.yaml` and the built
`init.tmux` to `$XDG_DATA_HOME/...` (both writable). The bundled `build.py` runs
under a wrapped python3 provided by the nixpkgs plugin, so the menu rebuilds on
first switch. Plan must set this option **before** the plugin loads.

## Files touched

- `modules/hm/tmux.nix` — **new**: static tmux module (options, keybindings,
  plugins, theme hook). Imported from `default.nix`.
- `modules/hm/default.nix` — remove inline `programs.tmux` block; add
  `./tmux.nix` to `imports`.
- `modules/hm/home/wallbash/tmux.dcol` — **new**: wallbash template source.
- `modules/hm/files.nix` — add `home.file` entry mapping the template to
  `~/.config/hyde/wallbash/always/tmux.dcol`.

## Risks & caveats

- **First populate:** `tmux.conf` does not exist until a theme/wallpaper is
  reapplied once after rebuild. Until then the mocha fallback shows. Plan should
  document a one-time "reapply theme to populate" step.
- **continuum vs `cz`:** mitigated by save-only + disabled auto-restore.
- **resurrect scope:** restores layout/cwd, not live Claude processes.
- **Socket/env:** reload depends on themeswitch running as uid 1000 with default
  `TMUX_TMPDIR`. Both hold today; note in plan as the thing to re-check if live
  reload ever stops working.
- **which-key dependency:** `tmuxPlugins.tmux-which-key` ships its own default
  config/generator; confirm it loads cleanly on first switch.

## Out of scope

- Following HyDE for anything beyond status-bar colors (e.g. fonts, layout).
- Persisting/restoring live agent processes (resurrect only does layout).
- Changing the prefix key or the `cz` session model.

## Manual verification (post-implementation)

1. `home-manager switch` (or nixos-rebuild) succeeds; tmux config valid.
2. New tmux shows mocha fallback before first theme regen.
3. Reapply theme/wallpaper → `~/.cache/hyde/wallbash/tmux.conf` appears and the
   running `main` session recolors live without restart.
4. `prefix + Space` opens the which-key menu.
5. `C-h/j/k/l` moves between nvim splits and tmux panes seamlessly.
6. tmux-fzf, extrakto, and clipboard yank work.
